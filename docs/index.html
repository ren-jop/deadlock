Deadlock

Sleep-window and distraction enforcement designed so the policy layer survives independently of the menu-bar UI.

SourceInstall preview
Status
v1.2.2 preview
Platform
Apple Silicon · macOS 14+

Lifecycle
launchd

Engineering problem

A sleep or distraction policy is ineffective if quitting the GUI also kills enforcement. Deadlock separates configuration from enforcement so the menu app can remain a thin controller rather than the trusted runtime.

Design

A privileged daemon owns schedule and policy state. An independent watchdog protects that daemon, IOKit wake events feed the sleep path, and local Unix-socket IPC provides a narrow control surface for the menu app and Focus.

The working sleep path deliberately preserves IOKit wake handling and pmset sleepnow while surrounding policy and UI continue to evolve.

Install

Preview warning: this installs privileged launchd services and uses the project's intentional uninstall-delay behaviour. Review the repository first.

git clone https://github.com/ren-jop/deadlock.git
cd deadlock
./install.sh

Failure boundaries

The UI is not the source of truth. Enforcement remains in the root daemon; Focus can request distraction protection over local IPC without taking ownership of Deadlock state.
