Deadlock

A privileged, event-driven macOS enforcement layer for sleep schedules and distraction policy. The menu UI can disappear; the policy engine keeps running.

Problem

Policy should survive the interface.

Most focus tools are easy to close because their enforcement lives with the UI. Deadlock moves schedule evaluation, sleep enforcement and web policy into a privileged daemon, leaving the menu-bar app as a controller rather than the authority.

Installation

One command after clone.

git clone https://github.com/ren-jop/deadlock.git
cd deadlock
./install.sh

The installer validates the vendored source snapshot, applies the current readable patch set, compiles a release build and installs the launchd services. No Xcode project or third-party dependency is required.

Architecture

Small UI, durable enforcement.

SwiftSwiftPMIOKitlaunchdUnix IPCAccessibility

Wake events are handled through IOKit, sleep enforcement uses macOS system tooling, and Focus communicates with the daemon over local IPC. Distraction blocking uses managed hosts entries with a browser-scoped fallback for connections that predate a DNS change.

v1.2.3

Web blocking reliability.

The current pass corrects IPv6 sink entries, adds mobile hostname variants, rescans browsers when a block begins, and adds a browser-scoped Accessibility fallback for already-open sessions. A new deadlockctl web diagnostic reports the managed hosts sections and resolver results.

Development

Temporary maintenance mode.

For debugging, ./maintenance-unlock.sh bypasses Deadlock's own settings-edit guards for the current daemon process only. The saved restrictions are not deleted; restarting the daemon restores them.

Verification

Preview, not a security claim.

The v1.2.3 source changes pass Swift parser checks and the install/diagnostic scripts pass shell syntax checks. Runtime website blocking still needs to be exercised on the target Mac because Accessibility permission, browser DNS behaviour and existing connections are OS/runtime conditions.
