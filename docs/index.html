Deadlock

I made Deadlock because I wanted sleep hours and website blocking that I couldn’t just close from the menu bar when I got annoyed with it.

Why I made it

I wanted something closer to Cold Turkey for my own workflow, but with sleep enforcement as well. The main requirement was that closing the interface should not disable the rules.

How it works

The menu-bar app edits settings and shows status. A root daemon handles the actual enforcement. It uses launchd to stay alive, local Unix sockets for communication, IOKit for sleep-related behaviour, and managed /etc/hosts entries for website blocking.

The watchdog is there because the enforcement process should not depend on the GUI being open.

Website blocking

If the weekly distraction schedule is off, the domains in the block list are blocked continuously. If the schedule is on, they follow those time windows instead. YouTube is the exception: browser and official-app access are blocked without changing YouTube DNS, so IINA can still resolve and play it. deadlockctl web shows the active policy, configured domains and hosts entries.

Install

git clone https://github.com/ren-jop/deadlock.git
cd deadlock
bash ./install.sh

Current state

The sleep path and distraction blocking are working on my Mac. The installable source is also built in macOS ARM64 CI so the repo tests the same source path that the installer uses.

What I learned

This project taught me a lot about launchd, privileged processes, IPC, macOS permissions, and why diagnostics matter when the thing you are debugging is supposed to keep running without a UI.
